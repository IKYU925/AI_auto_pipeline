# F09. Slack 장애 카드와 회신 형식

상태: 완료
관련: F08, plan.md 5장

## 문제

자동화의 Slack 회신은 결과, 분류, 원인, 수정 내용, 영향 범위, 테스트, 비용, 패치 diff를 한 덩어리 텍스트로 붙인다. 운영자는 스레드를 열어 끝까지 읽어야 무슨 장애이고 무엇을 해야 하는지 안다.

## 목표와 비목표

- 목표: 회신 첫 화면에서 결과(조치가 필요한지), 서비스, 장애, 원인, 수정 요약을 바로 읽을 수 있다.
- 목표: 패치처럼 긴 내용은 카드 밖(같은 스레드의 다음 메시지)으로 뺀다.
- 비목표: 장애 알림(shopapi가 올리는 메시지) 형식. 3단계에서 Alertmanager 어댑터(F04)가 입구가 되면서 바뀐다. 승인 버튼(F06), 고객사별 채널(F05).

## 운영자 시나리오

1. `#alert`에 장애 알림이 올라온다.
2. 30초 안팎에 스레드에 카드가 달린다. 머리 줄에서 결과를 보고(✅ 승인 대기, 📘 런북 안내, ⚠️ 담당자 확인), 그 아래 칸에서 서비스, 분류, 시도, 비용을 본다.
3. 원인과 수정 요약을 두세 줄로 읽는다. 패치를 보려면 다음 메시지를 연다.

## 요구사항

- 데이터: 워커의 최종 상태(결과, 장애, 분류, 원인, 수정안, 테스트 선별과 결과, 비용, 재사용 여부, 참고 문서, 중단 사유)에서 카드 하나를 만든다.
- 결과별 머리 줄과 표시

| 결과 | 머리 줄 | 본문 |
| --- | --- | --- |
| resolved | ✅ 수정안 검증 완료 · 승인 대기 | 원인, 수정 요약(위험도), 테스트 |
| no_code_fix | 📘 코드 수정 대상 아님 · 런북 안내 | 분류 요약, 참고 런북 |
| escalated | ⚠️ 자동 수정 실패 · 담당자 확인 | 원인, 마지막 테스트 결과 |
| budget_exceeded | 💸 LLM 비용 상한 도달 · 담당자 확인 | 중단 사유 |

- Slack Block Kit 한도(섹션 3,000자, 필드 2,000자)를 넘지 않게 긴 문장은 자른다. 알림 미리보기와 화면 낭독용 `text`는 머리 줄로 둔다.
- 패치는 resolved일 때만 카드 다음 메시지로 코드 블록에 넣는다.
- 상태 저장소의 `report`(텍스트 보고서)는 그대로 둔다. 로그와 API 조회용이다.

## 완료 기준

- [x] 결과별 카드 구성 테스트(머리 줄, 필드, 패치가 카드에 없음, 길이 한도)
- [x] 워커가 카드와 패치 메시지를 보낸다(가짜 클라이언트 테스트)
- [x] 실제 `#alert`에 카드 초안 한 건(실제 LLM S01, 약 $0.08)을 올리고 운영자가 형식을 확정한다
  - 2026-11-14 S01 초안 두 건을 올렸다(alert ts 1794642482.248239, 1794642583.653019). 같은 장애의 수정안이 이미 검증돼 있어 두 건 모두 재사용 경로로 처리됐고 LLM 비용은 $0이었다. 그래서 카드에 원인 칸이 없다. 운영자 확정은 대기 중이다.

## 설계 메모

- 카드 생성은 순수 함수(`app/notify/card.py`)로 두고 워커는 보내기만 한다. 형식을 바꿔도 워커와 그래프는 그대로다.

## 열린 질문

- 없음. 맨 위 줄은 결과(이모지와 제목)를 먼저 두고, 알림 미리보기 text에 서비스와 에러 첫 줄을 붙였다. 채널 목록에서 결과가 먼저 보이고, 알림 미리보기로 어떤 장애인지 알 수 있다.
