# F02. 최적화 끄기 옵션, 지표 수집, 반복 실행

상태: 구현 중
관련: plan.md 6장, 7장, 1-3~1-6

## 문제

"비용 최적화로 N% 절감"을 말하려면 최적화를 켠 조건과 끈 조건을 같은 시나리오로 반복해서 비교해야 한다. 지금은 최적화를 끌 방법이 없고, 시나리오 하나를 한 번 돌려 JSON 한 줄만 남긴다. 재발(S12)과 중복(S13)은 실행 절차가 없다.

## 목표와 비목표

- 목표: 최적화 다섯 가지를 서버 설정으로 각각 끌 수 있게 한다.
- 목표: 시나리오 여러 개를 조건과 반복 횟수를 정해 실행하고, plan.md 6장 지표를 CSV 한 파일로 남긴다.
- 목표: 기록한 조건(A, B)과 서버의 실제 설정이 같다는 것을 실행 전에 확인한다.
- 비목표: 개별 최적화의 기여도 측정(plan.md 7장 해석 규칙대로 묶음 비교만 한다), 결과 분석과 표 작성(1-6, 1-7).

## 운영자 시나리오

1. `.env`에서 `OPT_*`를 모두 켜고(A) 컨테이너를 다시 만든다.
2. `python -m scripts.run_experiment S01 S02 ... --condition A --repeat 3 --out results/phase1_A.csv`
3. 스크립트가 서버 설정이 A인지 확인하고, 실행마다 캐시를 비우고, 시나리오를 차례로 실행해 CSV에 한 줄씩 붙인다.
4. `OPT_*`를 모두 끄고(B) 같은 명령을 `--condition B`로 실행한다.

## 요구사항

- 설정(환경변수, 기본값은 모두 켬)

| 변수 | 켬(A) | 끔(B) |
| --- | --- | --- |
| `OPT_LLM_CACHE` | 분류, 원인 분석 응답을 캐시 | 매번 LLM 호출 |
| `OPT_MODEL_ROUTING` | 분류는 경량, 분석과 수정은 고성능 | 전부 고성능 |
| `OPT_EARLY_EXIT` | 비코드 장애는 분류 후 런북 안내로 종료 | 비코드 장애도 원인 분석까지 실행 후 종료 |
| `OPT_TEST_SELECTION` | 영향 범위 기반 선별 | 매번 전체 테스트 |
| `OPT_FIX_REUSE` | 검증된 수정안 재사용 | 재사용 안 함 |

- `GET /api/v1/config`(토큰 필요): 모델, 최적화 설정, 최대 시도 횟수, 장애당 예산.
- 워커가 상태에 남기는 값: 분류, 패치, 시도 횟수, 비용(모델별 호출 수, 작업별 호출 수, 캐시 적중), 테스트 선별(선별 파일 수 또는 전체), 테스트 결과(통과 여부, 실행 시간), 수정안 재사용 여부.
- 실행 절차

| 재현 방식 | 절차 |
| --- | --- |
| `requests`, `startup`, `alert` | 캐시 비움, 버그 주입(패치가 있을 때), 재현, 접수, 완료 대기, 판정, 원복 |
| `recurrence` | 캐시 비움, base 실행, 중복 제거 키만 지우고 캐시는 그대로 둔 채 같은 장애 다시 접수, 두 번째 결과를 기록 |
| `duplicate` | 캐시 비움, base 주입, 재현 1회, 같은 장애를 N번 연속 접수, 만들어진 장애 ID 수와 처리 결과를 기록 |

- 캐시 비움 대상: LLM 응답 캐시(`llm:*`), 검증된 수정안(`fix:resolved:*`), 중복 제거(`dedupe:*`), 검색 캐시(`rag:q:*`). 임베딩 캐시는 LLM 비용과 무관하고 로컬 계산이라 남긴다.

## 설계 메모

- 조건은 서버(api, worker 컨테이너) 설정이다. 스크립트가 바꿀 수 없으므로 `/api/v1/config`로 확인만 한다. 조건을 바꿀 때는 `.env`를 고치고 컨테이너를 다시 만든다.
- 스크립트는 접수 후 "처리 대기" 단계만 실제 워커에 맡긴다. 테스트에서는 이 단계를 프로세스 안 워커 실행으로 바꿔 끝까지 검증한다.

## 열린 질문

- 실제 compose 스택에서 스크립트 경로(조건 확인, 캐시 비움, 주입과 원복, 접수, 대기, CSV)는 확인했다. LLM 호출은 API 키가 유효하지 않아(401) 아직 확인하지 못했다.

## 변경 이력

- 2026-11-14 plan.md의 `OPT_CLASSIFY_CACHE`를 `OPT_LLM_CACHE`로 바꿨다. 캐시는 분류뿐 아니라 원인 분석 응답에도 걸려 있어서, 분류만 끄면 B 조건에 캐시가 남는다.
