# 0009. 검증 스킬은 사용 중인 스택과 분리된 별도 스택을 띄운다

상태: 채택(2026-11-14 검증 스킬 `.claude/skills/verify-aiops`로 구현하고 증명)
날짜: 2026-11-14

## 맥락

다음 에이전트가 자동화를 실제로 띄우고 증거를 남기는 검증 스킬(`/pstack:create-verification-skill`)을 만들기로 했다. 지금 compose는 호스트 포트(6379, 6333, 8000, 8100)가 고정이고, 버그 주입은 워커와 공유하는 `targets/shopapi`를 직접 고친다. 사용 중인 스택과 같은 것을 하나 더 띄울 수 없고, 검증 중 버그 주입이 사용 중인 스택에도 그대로 보인다.

## 결정

- 검증 스택은 compose 프로젝트 이름 `aiops-verify`, 포트 18000(api), 18100(shopapi), 16379(redis), 16333(qdrant)으로 띄운다. compose 덮어쓰기 파일의 `!override`로 포트와 볼륨을 바꾼다(Docker Compose 5.7에서 동작 확인).
- shopapi는 임시 복사본을 워커와 shopapi 컨테이너에 마운트하고, 실험 스크립트도 그 복사본에 버그를 주입한다.
- 증거(CSV, 장애 상태 JSON, 워커 로그)는 정리 단계에서 지우지 않는 위치에 남긴다.

본 실험(Day 5~6)은 기존 기본 스택(compose 프로젝트 `ai_auto_pipeline`)에서 돈다. 분리 스택은 검증 스킬이 기본 스택과 실험 결과를 건드리지 않게 하기 위한 것이다.

`!override` 동작은 `docker compose -p aiops-verify -f docker-compose.yml -f <덮어쓰기 파일> config --format json`으로 확인했다. api 포트가 18000:8000 하나로, worker의 `/repo` 볼륨이 지정한 경로 하나로 바뀌었다.

## 근거

- 검증이 사용 중인 스택과 소스를 건드리면, 검증 결과가 맞아도 사용 중인 실험 결과가 오염된다.

## 영향

- 실험 스크립트가 shopapi 경로를 설정으로 받아야 한다(지금은 고정 경로).

## 검토한 대안

- 사용 중인 스택을 그대로 쓰고 검증 중에는 다른 실험을 하지 않기: 규칙을 사람이 지켜야 하고 어기면 결과가 섞인다.
