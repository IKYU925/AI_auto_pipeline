# 0012. LLM 응답 캐시는 Redis에 남기고 장애 결과는 jsonb 칼럼에 둔다

상태: 채택
날짜: 2026-11-14

## 맥락

plan.md 8장은 Redis에 큐와 중복 제거만 남기고, 분류 캐시는 `incidents`에서 같은 지문의 최근 분류를 조회하도록 바꾼다고 적었다. 그런데 1단계 구현의 LLM 캐시는 분류만이 아니라 원인 분석 응답에도 걸려 있고, 키는 프롬프트 해시다(F02 변경 이력). 또 API가 돌려주는 장애 상태에는 plan.md 스키마에 없는 값(테스트 선별, 테스트 결과, 비용 요약, 패치 경로)이 들어 있다.

## 결정

- LLM 응답 캐시(`llm:*`)는 Redis에 TTL로 남긴다.
- `incidents`에 `result jsonb`, `report text`, `updated_at`을 더한다. 집계에 쓰는 값(상태, 분류, 시도 수, 시각)은 칼럼으로, 나머지 결과는 `result`에 둔다.

## 근거

- 캐시는 지워져도 다시 계산하면 되는 값이다. 영구 보존 대상이 아니고 TTL이 필요하다. 영구 기록은 `llm_calls`의 `cache_hit` 행으로 남는다.
- 분류만 `incidents`에서 찾게 바꾸면 원인 분석 캐시는 여전히 Redis가 필요해서 캐시가 두 군데로 나뉜다.
- API 응답 모양을 유지해야 실험 스크립트를 고치지 않고 1단계와 같은 조건으로 다시 돌릴 수 있다(2-6).

## 영향

- 2단계 전후 비교에서 캐시 적중률은 1단계와 같은 방식으로 측정된다.
- 대시보드(3-6)는 `result` 안의 값이 필요하면 jsonb 연산자로 꺼낸다.

## 검토한 대안

- 캐시를 PostgreSQL 테이블로 이전: TTL 정리 작업이 따로 필요하고 이득이 없다.
- `result`의 모든 값을 칼럼으로: 그래프 상태가 바뀔 때마다 마이그레이션이 필요하다.
