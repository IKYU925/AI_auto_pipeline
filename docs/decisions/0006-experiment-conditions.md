# 0006. 실험 조건은 서버 설정으로 두고 실행 전에 확인한다

상태: 채택
날짜: 2026-11-14

## 맥락

1단계는 최적화를 켠 조건(A)과 끈 조건(B)을 비교한다. 최적화는 api, worker 컨테이너 안에서 동작하므로 조건은 서버 설정이다. 실험 스크립트가 기록하는 조건 이름과 서버의 실제 설정이 다르면 결과 전체가 틀린다.

## 결정

- 최적화 다섯 가지를 `OPT_LLM_CACHE`, `OPT_MODEL_ROUTING`, `OPT_EARLY_EXIT`, `OPT_TEST_SELECTION`, `OPT_FIX_REUSE`로 끌 수 있게 하고 기본은 켠다.
- `GET /api/v1/config`가 실제 설정을 돌려주고, 실험 스크립트는 `--condition`과 다르면 실행하지 않는다.
- plan.md의 `OPT_CLASSIFY_CACHE`는 `OPT_LLM_CACHE`로 바꾼다. LLM 응답 캐시는 분류뿐 아니라 원인 분석에도 걸려 있어 분류만 끄면 B에 캐시가 남는다.
- 실행마다 LLM 캐시, 검증된 수정안, 중복 제거, 검색 캐시를 비운다. 임베딩 캐시는 LLM 비용과 무관한 로컬 계산이라 남긴다.

## 근거

- 조건을 사람이 기억하는 데 맡기면 컨테이너를 다시 만들지 않은 채 B를 기록하는 실수가 생긴다. 실행 전 확인으로 막는다.

## 영향

- 조건을 바꿀 때 `.env`를 고치고 api, worker 컨테이너를 다시 만들어야 한다(F02, README).

## 검토한 대안

- 요청마다 최적화 설정을 보내기: 운영 경로와 다른 코드가 생기고, 측정하는 시스템이 운영 시스템과 달라진다.
