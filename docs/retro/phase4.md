# 4단계 회고 자료

velog 4편 초안의 재료다. 수치와 근거는 [results/phase4_eks.md](../../results/phase4_eks.md), [results/phase4_runbook_hit.md](../../results/phase4_runbook_hit.md), [results/phase4_p0_resources.md](../../results/phase4_p0_resources.md), [docs/decisions/0014-eks-replaces-ec2.md](../decisions/0014-eks-replaces-ec2.md), 트러블슈팅 #19~#30에 있다.

## 만든 것

- 3단계의 자동화, shopapi 세 벌, 관측 도구를 같은 매니페스트로 EKS 클러스터 하나(Graviton 노드 2대)에 올렸다. 클러스터는 형제 저장소 infra_template의 Terraform이 만들고, 앱은 ArgoCD app-of-apps가 Git에서 배포한다. Terraform은 ArgoCD와 루트 앱 하나만 만든다.
- 클러스터는 실험할 때만 있다. `make eks-up`으로 만들고 `make eks-down`으로 지운다. 지우고 나면 남은 리소스를 태그로 검사한다. 코어타임(평일 09:30~12:00) 밖에서는 매시 정리 워크플로가 지운다.
- 분석 컨텍스트 두 가지를 넣었다. 알림 시점의 배포 이력(리비전, 이미지, 장애 몇 분 전)과 Pod의 상태와 K8s 이벤트다. 배포 이력은 로컬에서는 ReplicaSet에서, EKS에서는 ArgoCD Application 배포 이력에서 읽는다. Deployment의 ArgoCD 추적 표시로 어느 쪽인지 정한다.
- 승인 후 롤백을 EKS에서는 ArgoCD로 한다(`argocd-rollback`). Application의 이미지를 직전 배포 이력의 값으로 되돌리면 자동 sync가 배포한다. 대상은 고객사 shopapi Application 세 개뿐이고, 권한도 그 이름으로만 준다. 제안 뒤 배포가 바뀌었으면 롤백하지 않는다.
- shopapi를 고객사별 Application으로 나눴다. 고객사 하나의 롤백이 다른 고객사나 자동화 본체를 건드리지 않는다.

## 실패와 배운 것

- **루트 앱이 장애 주입을 1초 만에 되돌렸다(#29).** 하위 앱은 장애 주입 때문에 selfHeal을 껐지만 루트 앱만 켜져 있었다. 하위 Application 객체도 루트 앱이 관리하는 리소스라, 그 이미지를 바꾸면 루트 앱이 Git 값으로 되돌린다. 롤백도 같은 이유로 막힌다. 로컬에는 ArgoCD가 없어서 이 문제가 없었다. 앱 계층이 하나 늘면 "누가 이 객체를 관리하는가"도 한 단계 늘어난다.
- **실험 중 문서 PR 병합이 실험을 망쳤다(#30).** 루트 앱은 `main`을 보므로, 문서만 바뀐 커밋에도 다시 sync해 버그 이미지를 내렸다. 승인한 롤백은 리비전 확인에 걸려 실행되지 않았다. 안전장치는 맞게 동작했지만 측정은 버렸다. GitOps에서는 실험 중 `main`이 실험 환경의 일부다.
- **같은 시나리오가 환경마다 다른 길로 장애를 넣고 있었다.** EKS S21이 처음에는 `kubectl set image`를 써서 ArgoCD 배포 이력에 남지 않았다. 그대로 돌렸다면 "분석이 직전 배포를 못 본다"는 결과가 나왔을 것이다. 세션 직전에 실행기를 ArgoCD 배포로 고쳤다. 장애 주입 경로가 실제 배포 경로와 같은지 먼저 확인해야 한다.
- **port-forward는 Pod가 바뀌면 끊긴다(#27).** EKS에는 인그레스가 없어 port-forward로 요청을 넣었는데, 버그 이미지 배포로 Pod가 바뀌자 연결이 끊겨 장애 요청이 들어가지 않았다. 실행기가 연결 오류도 다시 보내게 고쳤다.
- **세션이 끝난 뒤의 승인 카드는 눌러도 반응이 없다.** 클러스터를 내리면 승인 처리 Pod도 사라져 클릭을 받을 곳이 없다. 실험 환경에서만 생기는 일이라 고치지 않고 기록만 했다.
- **비용 안전장치가 실험을 막을 수도 있었다(#24).** 코어타임 밖 정리 워크플로가 시험 중인 클러스터를 지울 수 있어, 당일 13:00까지 연장하는 변수를 만들었다. 연장 한도를 넘는 세션은 정리 시각 전에 끝나도록 시나리오를 줄였다.
- **Cost Explorer는 바로 반영되지 않는다.** 세션 당일에는 비용이 0으로 나와, 실험 기간 비용은 다음 날 이후에 채운다.
